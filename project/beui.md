# BEUI

***React와 Vue로 각각 구현된 Headless UI 컴포넌트 라이브러리***

![frog main](/img/preview/beui_vue_main.png)
  
</div>

## 문제

스타일 분리 이후에는 Vue 프레임워크 없이 빠르게 테스트 코드를 작성하거나 레거시 코드를 다룰 때 독립된 스타일 시스템과 *vanilla Html*를 조합하는 방식이 유용했습니디. 하지만 이후 기존에 사용하지 않았던 *React* 프로젝트를 진행하면서 컴포넌트 대신 *Html*만 사용해서 구현하는것은 한계가 있아고 생각하게 되었습니다. 그떄 본격적으로 *React*를 사용하기로 결정했던 시기였기 때문에 이후 개발 생산성을 높이기 위해 *React*에서도 **Frog UI** 적용이 가능한 라이브러리를 만들기로 했습니다. 이전까지는 *Headless UI*에 대한 개념을 사용해본적이 없었는데 이떄를 계기로 이 방식의 장단점을 고려해서 기존 Vue 컴포넌트들을 기반으로 동일한 기능을 제공하는 라이브러리를 만들게 되었습니다.   


## 주요 특징

- React, Vue 각각에 최적화되어 구현된 Headless UI 라이브러리
- 26개 컴포넌트 포함
- **Floating UI**라이브러리를 활용한 안정된 위치 지정 기능 제공


## 상세 내용

**프레임워크 최적화**

보통 UI 컴포넌트 라이브러리는 특정 프레임워크 기반으로 제작됩니다. 하나의 프레임워크로만 작업한다면 문제가 없지만 여러 프레임워크를 사용한다면 동일한 스타일과 기능을 유지하기가 쉽지 않습니다. **BEUI**은 스타일을 **Frog UI**에 위임한 Headless 컴포넌트 킷으로 현재 React, Vue 각각에 최적화된 라이브러리로 구현되어 있습니다. 동일한 스타일로 랜더링되는 컴포넌트가 각 프레임워크에 최적화된 기능을 제공합니다. 동일한 UI를 여러 프레임워크로 구현하는 과정에서 Vue의 `slot`, React의 `compound pattern`처럼 각 프레임워크의 고유한 기능을 최대한 활용했고 여기에 더해 서로 다른 프레임워크의 장점을 내부적으로 교차 구현하여 더욱 강력한 성능의 컴포넌트를 만들게 되었습니다.

**추가된 컴포넌트들**

**Frog UI**로 부터 스타일을 제공받다 보니 지원받는 컴포넌트 종류도 동일할것 같지만 실제로는 **BEUI**에만 존재하는 컴포넌트들이 있습니다. 몇몇 컴포넌트는  *Javascript*를 이용한 동적 기능이 필요하기 떄문입니다. 현재 `InputNumber`, `Rate`, `Slider`, `Calender`, `DatePicker`, `Pagination`이 프레임워크 기능을 활용하여 동작하도록 추가되어 있습니다. (최근 **Frog UI**에서 위 컴포넌트들도 독립적으로 기능을 수행 할수 있도록 *vanilla javascript*를 활용한 기능 추가를 진행하고 있습니다.)

**Froat UI의 활용**

자체 라이브러리를 사용하는 방식은 항상 안정성 부족이라는 이슈를 갖고 있습니다. UI 컴포넌트의 여러 기능중에서도 *floating*이나 *popping* 같은 기능은 직접 구현하려면  고려할 사항이 많이 때문에 특히 더 이슈가 됩니다. 그래서 **BEUI**에서는 이 부분에 **Floating UI** npm 모듈을 사용하도록 결정했습니다. 검증된 모듈 적용으로 라이브러리 전반의 안정성이 높아지고 레이어 우선순위 문제나 뷰포트 충돌처럼 직접 구현하기 까다로운 기능들을 안정적으로 처리할 수 있게 되었습니다. **BEUI**의 `Selectbox`와 `DatePicker` 컴포넌트에 적용 되어있습니다.

**Headless의 장점**

**BEUI**는 Headless 라이브러리이지만 다른 Headless 라이브러리와는 달리 **Frog UI**스타일에 최적화 되어있어 완전하게 디자인 자유도를 갖는다고는 할 수 없지만 정해진 스타일 안에서 별도의 기능 구현 없이 복잡한 기능의 UI 컴포넌트를 쉽게 적용할 수 있습니다. 또한 라이브러리 패키지에서 스타일 코드가 차지하는만큼 용량만큼 전체 크기가 줄어들기 떄문에 프로젝트에 적용했을 떄 번들 크기 측면에서도 유리합니다. 또한 라이브러리의 업데이트를 하거나 적용된 컴포넌트를 편집할때도 기능 로직에만 집중할 수 있다는것 역시 장점입니다. 


## 결과

Frog UI와 BEUI를 함께 운영하면서 스타일과 기능을 분리해 설계하는 것이 왜 중요한지 실감할 수 있었습니다. 스타일 시스템만으로는 프레임워크가 달라지는 상황에 대응하기 어려웠지만, Headless 구조로 기능을 별도로 분리하면서 새로운 프레임워크가 도입되더라도 기존 자산을 재사용할 수 있는 유연한 구조를 갖추게 되었습니다. 앞으로도 특정 기술에 종속되지 않으면서 여러 프로젝트에서 안정적으로 활용할 수 있는 구조를 고민하며 시스템을 발전시켜 나갈 계획입니다.
